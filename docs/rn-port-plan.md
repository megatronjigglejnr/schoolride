# React Native port plan

The HTML prototype in `app/` is the spec for every screen, state and rule. It stays untouched, with its Playwright tests, as the reference. The port lives in `mobile/`.

**Stack**
- Expo (latest SDK) with TypeScript and Expo Router.
- Libraries:
  - `react-native-reanimated`
  - `react-native-svg`
  - `expo-glass-effect` / `expo-blur`
  - `expo-linear-gradient`
  - `react-native-safe-area-context`
  - `@expo-google-fonts/archivo`
  - `Linking` for `tel:`
- State: one React context for the active child. No other state library.
- Maps: no real maps yet; the hand-drawn SVG maps are ported.

**Process.** Each phase ends with:
1. Expo web checked in the Browser pane at 390x844, side by side with `app/index.html`.
2. The tests that exist so far run green.
3. The Expo Go command for a phone check.
4. A stop for review.

Nothing is committed unless asked.

## How the prototype maps to React Native

These are the places where a 1:1 mapping isn't possible. Each one gets the closest option, flagged here so nothing changes silently.

| Prototype | React Native | Note |
|---|---|---|
| CSS tokens and `rgba(var(--ink-rgb), a)` | `tokens.ts` with the same names and values, and an `alpha(color, a)` helper | Generated by hand from `app/styles.css :root`; a test checks the two stay equal |
| Two-layer `box-shadow` | RN `boxShadow` style (new architecture, iOS, Android and web) | Same values |
| `backdrop-filter` glass | `GlassView` when `isLiquidGlassAvailable()` (iOS 26+); otherwise `BlurView`; solid fills when Reduce Transparency is on | `isReduceTransparencyEnabled` is iOS-only. Android `BlurView` needs `experimentalBlurMethod`, otherwise it falls back to a translucent fill. Blur budget unchanged |
| Tab-bar highlight that follows the pointer (`--mx`, `--my`) | Dropped on native; web only | Touch has no hover |
| `inert` on closed layers | Closed layers unmounted, or `pointerEvents="none"` + `accessibilityElementsHidden` / `importantForAccessibility="no-hide-descendants"` | Same effect for screen readers and taps |
| `::after` tap-area extensions | `hitSlop` | Visual size unchanged, 44pt hit area |
| `:focus-visible` ring | Web: the same ring via `focus` styles; native: the system focus | |
| `role="status"` toast | Toast + `AccessibilityInfo.announceForAccessibility` | |
| `prefers-reduced-motion` | `useReducedMotion()` (Reanimated) / `AccessibilityInfo.isReduceMotionEnabled` | Same rule: no animation |
| Hand-written SVG strings (bus, icons, maps) | `react-native-svg` components | Map maths ported unchanged |
| CSS dotted transit line | SVG lines | |
| Scroll-snap carousel on the full map | Horizontal `FlatList` with `snapToInterval` | Swipe still changes the active child |
| `tel:` with a `DEMO_CALLS` toast | `Linking.openURL('tel:…')`, `DEMO_CALLS` flag kept | |
| OTP paste and `autocomplete=one-time-code` | `textContentType="oneTimeCode"`, `autoComplete="sms-otp"`, and a 6-digit paste into any box fills all six | |
| Phone `<input type="text">` (CLAUDE.md gap 2) | `keyboardType="phone-pad"`, `autoComplete="tel"` | The native default; fixes that gap. Flagged, not silent |
| Demo controls ("Simulate signal loss", "Skip onboarding", code hint) | Kept, labelled "(demo control)", behind one `DEMO` flag | |
| Header turns frosted when content scrolls under it | Each tab's `onScroll` sets a shared header state | |
| Sheets with full-screen scrim | In-tree `Sheet` component over the tab layout (not a native modal), so the scrim, glass and FAB layering match | |

## Open questions
- Glass on Android: `BlurView` with `experimentalBlurMethod="dimezisBlurView"` is the only real blur, and it costs performance. Proposal: translucent fills on Android (the same look as the `@supports` fallback), and real glass on iOS and web only.
